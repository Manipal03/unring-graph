# unring-graph

**"If I undo this agent action, what else breaks?"** The effect ledger of [unring](https://github.com/Manipal03/unring), stored as a graph in Relate.

## Use case

AI agents chain tool calls. One call writes a file, the next reads it and posts to Slack, a third emails it to customers. When a human says "that first step was wrong, undo it", undoing that one call isn't enough. Everything downstream that *consumed* its output is now stale, and some of it can't be taken back.

[unring](https://github.com/Manipal03/unring) already gives agent tool calls transactions: a hash-chained effect ledger plus saga-style rollback. That ledger is flat, though. It records *what* happened but not *what depends on what*. This project rebuilds the ledger as a graph so the following questions become one traversal each:

- **Blast radius:** which later calls read what this call wrote, directly or transitively?
- **Safe undo order:** in what order do I compensate so nothing is undone out from under a dependent?
- **Stranded effects:** which dependents can't be cleanly undone (irreversible, partially reversible, or never tested), so a human has to follow up?
- **Hotspots:** which resources have the most downstream readers?

The relationships that matter are **call → resource** (read/write) and the derived **call → call** `DEPENDS_ON` (B read something A wrote earlier). Those are joined with **call → tool** and a measured reversibility verdict on each tool.

## How it uses Relate

- **Mode:** single file (`data/unring.rl`)
- **Why this mode:** an agent session's ledger is one unit of work, so it belongs in one artifact. A single file can be committed, attached to an incident ticket, or handed to a reviewer, and judges can inspect exactly one thing. unring runs in-process with one writer per agent session, which matches Relate's embedded, single-process model with no server to run.
- **What the graph models:**

```
(:Run {id})-[:MADE]->(:Call {id, seq, tool, reversal, risk, args, status})
(:Call)-[:OF]->(:Tool {name, verdict, inverse, residual_diff})
(:Call)-[:TOUCHED {op: 'read'|'write'}]->(:Resource {uri})
(:Call)-[:DEPENDS_ON {via}]->(:Call)      // derived: read-after-write
```

Tool verdicts are measured, not labelled. Before the run, `demo.py` executes each tool once in a sandbox, applies its undo, and diffs the observable state. An empty diff gives `reversible`, a leftover diff gives `partially_reversible` (the diff is stored as evidence), and no undo at all gives `irreversible`. A tool that couldn't be tested is stored as `unknown`, never assumed safe.

## Setup and run

Prerequisites: Python 3.10+ and git.

```bash
python -m venv .venv
```
```bash
.venv/Scripts/activate      # Windows; on macOS/Linux: source .venv/bin/activate
```
```bash
pip install -r requirements.txt
```
```bash
python demo.py
```

`demo.py` probes the tools, runs a scripted 7-call "release agent" through unring, builds the Relate store, and prints the report for undoing call #1:

```
Blast radius (calls that consumed its output):
  hop 1: #3 files.write    [reversible] read file:notes.md
  hop 1: #4 slack.post     [partially_reversible] read file:notes.md
  hop 1: #5 email.send     [irreversible] read file:notes.md
  hop 2: #6 docs.publish   [reversible] read file:changelog.md
  hop 2: #7 crm.note       [unknown] read slack:#releases

Safe undo order (newest dependent first):
  1. #7 crm.note  ...  6. #1 files.write

Cannot be cleanly cleaned up:
  #4 slack.post [partially_reversible] residue: [... "deleted": true ...]   <- Slack leaves a tombstone
  #5 email.send [irreversible] ...                                          <- customers already have it
  #7 crm.note [unknown] residue: never tested, so nothing can be claimed
```

Query the committed store directly, with no rebuild:

```bash
python blast_radius.py data/unring.rl
```
```bash
python blast_radius.py data/unring.rl --call 1
```

### Ask it from a coding agent (MCP)

With the [Relate CLI](https://relatedb.ai/docs/get-started/install) installed, expose the store read-only over MCP. For example, in Claude Code:

```bash
claude mcp add unring-graph -- relate serve --mcp stdio --database data/unring.rl --read-only
```

Then ask: *"Using unring-graph, what would break if I undid call 1?"*

## Where the data lives

- `data/unring.rl`: the Relate store (single file), the graph described above
- `data/ledger.sqlite`: the raw unring ledger it was built from (hash chain verified on every run)

Both are regenerated by `python demo.py`.

## Files

| File | What it does |
|---|---|
| `ledger_to_graph.py` | Reads an unring ledger and writes the Relate graph, deriving `DEPENDS_ON` edges |
| `blast_radius.py` | The Cypher queries (blast radius, undo order, stranded effects, hotspots) plus a command-line interface |
| `demo.py` | Fake tools, the reversibility probe, the scripted agent run |

The tools act on an in-memory fake world so the demo needs no credentials. unring and Relate are the real libraries.
